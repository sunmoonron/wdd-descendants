# 59. Classes defined in the prompt (S132)

**Question.** With the weights frozen no row can be recruited. Does a class that exists only in the prompt get a native word, borrow its label's words, ride reusable slot rows, or travel without a word?

**Established.**
- A class defined only in the prompt (eight objects sorted into two groups named by arbitrary capital letters) is carried at the object's later, letter-free mention in 4 of 6 models (Pythia-410m, Pythia-1.4b, OLMo-1B, SmolLM2-360M; leave-one-out decoding of the group from twin prompts 0.96, 0.89, 0.88, 0.85 at the clearest depth, against null means of 0.49 to 0.50), and not at any tested depth in GPT-2 medium and Qwen2.5-0.5B, which still answer the group question (0.83, 0.84) (e641).
- Where it is carried the identity code has no native word: the class direction's nearest write row sits at a median percentile of 0.21 to 0.76 among the same prompt's random-split directions, and it is not the letters' own features (median cosine with the letters' contrast +0.04 to +0.12), while the same statistic finds the animal-object direction's row above every random split in 5 of 6 models, a row whose top tokens read animal words in several (e641).
- The ordinal code (which group was named first) is shared across prompts with different letters and objects in the carriers (mean pairwise cosine up to Pythia-410m 0.74, Pythia-1.4b 0.55, OLMo-1B 0.42, SmolLM2-360M 0.37, nulls 0.01 to 0.07), a binding-ID-like code; its average has a nearest row above its null in OLMo-1B, SmolLM2-360M at some depth, a lead only, because the null for an average of random splits is less structured than any real code (e641).
- Reading: in the models that carry an in-context class forward at all, it travels as a code that the model's own write rows do not speak, as the recruitment law predicts with the weights frozen; WDD, and any tool built on native words, is blind to what a model learns in context.

**Session 133 (stored or held).** Fine-tuning stores sixteen objects' group letters in 10 to 25 steps (held-out query 1.00 to 1.00, neutral-text loss change -0.000 to +0.196 nats), and the object's state in a neutral sentence with no group statement in context carries the stored group in 4 of 4 runs (gate 0.94 to 1.00 at half depth). The stored class direction's nearest write row sits at a percentile of 0.40 to 1.00 among the same twin differences' random splits at half depth (0.32 to 1.00 over all three depths), against 0.05 to 0.58 for the same assignment held in the prompt. Reading: the thermometer leans the right way but does not reach its bar: in every run the stored class's direction sits closer to a write row than the same class held in the prompt (by +0.13 to +0.81 in percentile), and in 1 of 4 it clears 0.95 with a recruited, unrotated row; a fine-tune of 10 to 25 steps stores the fact mostly without giving it a word, so at this scale the statistic separates stored from held only weakly, and e579's native excess, which separated generalising from memorising runs of a toy, does not carry over to whether one fact is stored.

**Session 135 (stored, trained longer).** Trained past storage with the twins compared at equal steps, the stored class's nearest-row percentile at half depth is 0.93 to 0.98 in Pythia-410m's three seeds after 10 steps and 0.98 to 0.99 from 20 steps to 1280, 0.90 to 0.93 in GPT-2 medium throughout, and in Pythia-160m it climbs from 0.30 at 10 steps to 0.61 at 40 and then stays (0.63 at 1280); the neutral-text loss meanwhile reaches +0.50 to +0.66 nats in Pythia-410m, so longer training adds damage, not words. Correction to session 133: e643 stopped each twin at its own convergence, and Pythia-410m seed 1's twins stopped at 15 and 10 steps (GPT-2 medium's at 25 and 20), so those twin differences mixed the class with unequal training; compared at equal steps, Pythia-410m's stored class clears 0.95 in all three seeds from 20 steps on, which turns e643's thermometer from one run in four into every Pythia-410m seed, while GPT-2 medium and Pythia-160m stay below the bar.

## How the results flow

- `e643 → e646`: the stored side trained on, at equal steps.
- `e641 → e643`: the same classes held in the prompt and stored in the weights, read the same way.
- `e584, e632 → e641`: in pretraining the class forms before its row and the row's early lead is persistence; with no training at all the class forms and no row speaks it.
