# WDD on a looped model: Ouro-1.4B (2026-10-02)

Ouro-1.4B runs one stack of 24 layers four times with shared weights, an RMSNorm with a learned gain between passes, sandwich norms on every branch, and a learned exit gate. The comparison model is SmolLM2-1.7B: same width, 24 layers, same tokenizer. Data: WikiText-2 test, 8 to 32 sequences of 256 tokens. An fp32 forward written for this study matches Ouro's official modeling code to 5e-5 and SmolLM2's Hugging Face implementation to 8e-4. Scripts are in `scripts/looped/` (`run_all.sh` for the GPU steps, `run_cpu.sh` for the CPU steps; `./run` is a local wrapper that puts the venv's python on the path), results in `results/looped/`. Two 8 GB P4000s and the CPU, about three hours.

Prior art, checked the same day: nobody had read a looped language model with a weight-derived or sparse dictionary, or spliced a sparse code into one. Closest: per-layer fixed points in looped models (arXiv 2604.11791), the Jacobian lens on Ouro and Huginn (2609.01924), quantization error building up across Ouro's loops (LoopQ, 2605.16343). Caveat: Ouro's first 3T pretraining tokens used 8 loops, so loops 5-8 are past the trained exit but not unseen.

## Results

| Question | Answer |
| --- | --- |
| Does WDD read a looped model? | Yes. The state before layer 12, replaced by 16 native atoms, keeps 89% of the loss in loop 1 (rotated dictionary 30%, one-shot cosine 79%, PCA 39%), 79/66/52% in loops 2-4. SmolLM2's layer 12: 69%. |
| The state handed to the next loop | At 64 atoms the boundary code keeps 92/87/82% (boundaries 1-2, 2-3, 3-4); one-shot cosine 31% or less, PCA 49-57%, rotated 77/83/84%, so the edge over rotated is gone by the last boundary. Kept alone, the code's embedding atoms give 45% falling to 24%, its MLP atoms 37% rising to 48%, its attention atoms 7% or less. |
| Do loops repair errors? | A single one, yes: the 64-atom code's residual injected mid-loop 1 costs +2.33 nats at the loop-1 exit, +0.97, +0.18, +0.08 at exits 2-4; loops 5-8 repair much less and leave a residue. With 12 layers to the exit the same splice costs Ouro +0.75 and SmolLM2 +0.37. The residual hurts about 6x more than a random direction of the same size (+0.41) or a random native atom (+0.40); scaling the token's own first atom hurts least (+0.14). |
| Can the code stand in everywhere? | No. One 64-atom splice per loop: +2.15 (rotated +4.76). Six splices inside loop 1: +4.45, inside loop 4: +5.37, so later loops remove 17% of heavy damage against 89% of a single splice's. Twenty-four splices: Ouro +7.64 (k128 +7.16, rotated +7.43), SmolLM2 +6.65 (six: +4.14, rotated +7.60). |
| Same machinery every loop? | Loop 1 is its own stage, loops 3-8 one machine. Exact ledger: the top-1000 neurons by write energy overlap loop 4's at 0.07 (loop 1), 0.66 (loop 2), 0.82-0.91 (loops 3-8); per-neuron coefficients correlate 0.47, 0.75, 0.91, then 0.97-0.99 between successive loops. From the state alone, the 256 most used native words overlap loop 4's at 0.39 (loop 1) and 0.78-0.84 (loops 3-8), rotated dictionary 0.34-0.41. |
| Carry or recompute? | Recompute. Before layer 12 only 4-9% of the loop's input is left along its own direction, and 77-82% of the previous loop's eight largest writes per token are erased; the loop then rebuilds an output close to its input (cosine 0.79-0.84 from loop 3 on). The BOS sink is rebuilt every loop (10-15x the median norm mid-loop). |
| Which loop wrote what? | Not from directions: one between-loop norm leaves a write at cosine 0.99 with its atom (MLP 0.991, heads 0.987, embeddings 0.973), three at 0.90-0.94. The ledger answers it. |
| Does the exit gate know when to stop? | After loops 2 and 3 the gate predicts whether the next loop lowers a token's loss by 0.05 nats at AUC 0.77 and 0.65, exit-state change at 0.56 and 0.58, the change of the WDD code at 0.50 and 0.53. Per-token codes are unstable: from loop 4 on, successive 16-atom supports overlap 0.58-0.72 while the centred states sit at cosine 0.99. |
| Silent computation | From loop 1 to 2, 60% of tokens keep their top-1 prediction and 74% of those still gain 0.05 nats. Whether a token that kept its prediction from loop 2 to 3 flips later is predicted by the shift of the next-token distribution (AUC 0.72), not by the code's change (0.54). |
| Past the trained exit | Loss by loop 5.19, 3.35, 2.90, 2.87, 2.86, 2.90, 2.92, 2.94. For tokens that keep their prediction, an extra loop after loop 4 helps 18-25% and hurts 22-34%. The vocabulary stays (0.78 with loop 4) and 64 atoms still keep 91-98%. |

## Where WDD fits

Narrowly: a faithful, named snapshot of the state one pass hands the next, read in one vocabulary for every loop. For the dynamics (when to stop, which loop wrote what, how a token's state moves between loops) the exit gate, the shift of the prediction and the hooked neuron ledger do better, and the per-token code is too unstable to track them. The loop-boundary number (92% at 64 atoms against 31% for one-shot cosine ranking) is the strongest WDD-over-cosine result so far. Untested: compressing the handover (64 index-coefficient pairs against 2048 numbers), and Huginn, whose linear input injection re-mixes the state every step and breaks the assumption that writes keep their direction across steps.
