# WDD since 2016: a backcast and a roadmap

Prompt (the user, session 45): if Weight-Dictionary Decomposition had existed for ten years, what would the world look
like, and how do we get there from a method a few weeks old?

Method. Each imagined capability is reduced to the assumption it rests on. None of these assumptions was tested in the
400+ earlier experiments, which only measured function on pretrained checkpoints. Each gets the cheapest decisive test.

## What this changes about the path

- The dictionary a model ships with is its own weights. Its most useful words for a reader are concept words, and they can be found without labels. Look for words shared by translations, or more generally by paraphrases, of the same content. e448d found 15 such words for 24 nouns in a 0.5B model and 22 in a 7B model, in minutes.
- Interoperability should not be built on word tables. The models' words are private one to one, even for three Pythia sizes trained on the same data in the same order. Linear maps between whole states work (0.85-0.91), and a learned linear decoder from one model's 16-word description recovers as much of another model's function as that model's own 16 words.
- The theory has a first causal fact: training the writers creates the vocabulary. Training dynamics are now the place to explain it, for example the per-block accent that turns into words between steps 4000 and 16000 in Pythia (session 44).

## Roadmap (each step a short experiment)

1. Concept dictionaries at scale. The model translates a few thousand of its own sentences; words shared across translations and rare elsewhere are collected. Qwen2.5-7B already gives 22 of 24 nouns; next, many more concepts and all five models.
2. A vocabulary card per model: self-description curve (own, rotated, covA) by depth, the huge directions with sinks excluded, the concept-word list, and Zipf. Minutes per model with the session-44 and session-45 scripts.
3. Monitoring on real training: the word-level advantage across Pythia checkpoints around known transitions (induction heads), and more algorithmic tasks, to see whether the early signal holds.
4. The written-vocabulary theory at language-model scale: freeze writer or reader rows while pre-training a small model on real text, then follow the per-block accent turning into words.
5. Interpretability by design with a functional objective: fine-tune with the loss of the model run on its own 16-word description at one depth (differentiable through the least-squares fit), and measure the cost against the gain in functional self-description.
6. A native codec that pays less per index: entropy-code the indices using their Zipf-like frequencies (session 38), and code them per block, which should cut the index cost (not tested).
7. Steering with native words (added in session 46; first test e458). At natural size a concept word moves 35-58% of translations, and a dense difference of means 82-100% with 4-6 times the displacement. Next: more concepts and tasks, and combinations of a few native words.

## Session 128 (2026-10-11): the proxy tool, scoped by what Neuronpedia's API gives for free

The idea: a Charles-shaped viewer for model internals (sessions, a tree of units, frames per position, rules as files, compare, a training axis), built first as a client of Neuronpedia's public API so that no GPU is needed for its first version. Read from the API reference and the status page on 2026-10-11:

- Inference is live for gemma-2-2b (two servers), gemma-2-2b-it, gemma-2-9b-it, gemma-3-270m/1b/4b/12b, gpt2-small, llama3.1-8b and 8b-it, llama3.3-70b-it, gpt-oss-20b, qwen3.6-27b, deepseek-v4-flash; graph servers for gemma-2-2b (clt-hp and gemmascope-transcoder), gemma-3-4b-it, qwen3-1.7b, qwen3-4b; NLA servers for gemma-3-27b-it, llama3.3-70b-it, qwen2.5-1.5b-it; a circuit-sparsity server for OpenAI's weight-sparse model (connected-neurons with explanations).
- Endpoints that map onto the viewer: search-topk-by-token (top 20 features per token for a source: the Grid for SAE and transcoder sources, text up to 1000 characters); activation/new (one feature or custom vector per call, per-token values); lens/prompt (logit lens and Jacobian lens per position and layer, streamed, with steering and ablation options and up to 1024 generated tokens: the waterfall row, with chat support); graph/generate (attribution graph for a prompt of at most 64 tokens, documented for gemma-2-2b, returns a saved graph: the Follow view); steer and steer-chat (features or vectors with strengths, SIMPLE_ADDITIVE or ORTHOGONAL_DECOMP, default against steered text with logprobs: the Rules, output side only); vector/new (an arbitrary vector of the model's dimension at resid-pre or resid-post of a layer, up to 24576 dimensions, then usable as a feature: the model's own write rows can be pushed as vectors, so native units run on their GPUs); nla/explain (natural-language description of the residual state at up to 16 positions, three models, 120 requests an hour per IP); feature pages and explanations for labels.
- The code is Apache-2.0 and the inference server self-hosts one model at a time from a Hugging Face id with SAELens sources, so the same API contract can serve models Neuronpedia does not (Pythia checkpoints on a Mac for 160m, anything else on a rented GPU), extended with the program's own endpoints (ledger frames, floor, coalitions) which the public API lacks.

Holes this plan carries: whether activation/new accepts custom vectors is untested; one feature per activation call makes a native-row Grid expensive on the public API, so native rows there are a curated set and the full dictionary needs the self-hosted server; rate limits are undocumented except for NLA, so a cache and a local recorder are mandatory; the public steering returns text, not internals, so internals under intervention need the lens's steering options or self-hosting; graphs are documented for one model; data terms for redistributing their outputs are unstated; the viewer's unit abstraction must cover SAE features, transcoder features, custom vectors, graph nodes, NLA positions and sparse-model neurons; and the first version is a Neuronpedia client with a Charles skeleton, so the differentiation only arrives with the recorder, rules as files, compare across sessions and the self-hosted extension.

## Manifold tangents (2026-10-12, side-tangent from the LessWrong post "Manifolds for five-year-olds" on Goodfire's block-sparse featurizers)

Prior art: block-sparse featurizers (Fel et al., Goodfire, arXiv 2606.25234; follow-up arXiv 2608.27515) treat a representation as a sparse sum of low-dimensional manifolds, each carried by a block of learned directions, scored by description length; Engels et al. 2024 (arXiv 2405.14860) found circular features for days and months by clustering autoencoder features and intervened on the circle; Park, Choe and Veitch (ICLR 2025) found categorical concepts as polytopes. None names the parameters that implement a manifold or follows one through depth or training. Ideas, cheapest first:
1. A floor for blocks: the extreme-value floor extended from directions to d-dimensional subspaces (the maximum over blocks of a unit state's projected norm, Beta-tailed, calibrated on rotated blocks), a significance test block-sparse featurizers lack; may explain why most of their blocks look meaningless.
2. Session 137 (e647b, e648b): calendar subspaces carry a second anchored row (except Pythia-160m's months at this depth) and random-noun subspaces none, but only when the floor's null comes from the subspace's own states. Session 136 (e647 to e649): autoencoder blocks built as Engels et al. did pass the spectrum-matched floor almost always (0.93 to 1.00), so the floor cannot sort them; arbitrary noun class subspaces pass it in 0.21 of draws against the calendar's 0.91. Session 135 (e645, e645b, e646): the calendar's class-mean subspace has a write row deeper inside it than spectrum-matched rotations of itself in 20 of 22 model-calendar pairs, with or without block 0, Pythia-410m excepted; tangent 1's block floor, run. Session 134 closed fine-tune diffing by word usage (e644): zeroing WDD's top-ranked rows erases less of a planted fine-tune change than the plain activation change or the weight change in three of four runs and no more than random rows in two, at a high general cost. Session 133 stored the same classes by fine-tuning (e643): the same group letters stored by fine-tuning are carried at a neutral mention in 4 of 4 runs, with the nearest write row at percentile 0.40 to 1.00 among random splits against 0.05 to 0.58 held, above the held class in every run but past 0.95 in only 1. Session 132 located what the answer reads (e640, e642): the answer reads the name token through its class-mean subspace, which transfers the source's answer as well as the whole state in all 22 pairs while its complement transfers nothing. A class defined only in the prompt travels without a native word (e641), so a viewer built on native words will not see what a model learns in context. Session 131 rotated the writers (e639): rotating the writers' in-plane write components by one class step turns the ring by +0.57 to +1.56 of a step at the best block (GPT-2 small days +0.87, +0.89 at the last block, GPT-2 small months +0.88, +0.89 at the last block, SmolLM2-135M days +1.19, +0.54 at the last block, OPT-125m days +0.87, +0.87 at the last block, OPT-125m months +0.97, +0.98 at the last block), with the dose and the sign, at a loss change of at most +0.02 nats, while matched and random rows turn it by at most 0.15; the answers follow only in part: in the pairs where deleting the writers had cut the task the next-but-one share rises by +0.02, +0.11, +0.00, +0.25, +0.14 (GPT-2 small months, GPT-2 medium days, GPT-2 large months, SmolLM2-135M days, SmolLM2-360M days) and the rest of the lost answers smear, so the ring is at most a partial medium of the arithmetic here and in GPT-2 a correlate. Session 130 pushed this to its edges (e634 to e638): phase coding real and block-0, writers distinct from detectors and causal for the arithmetic in some models. Run as e633 (session 129, atlas area 57): the rings are there, the embedding's plane is abandoned, the MLP rows build a new one, diffusely in five of six models, with phase coding in four. Native blocks are coalitions: test whether a word's producer coalition traces a low-dimensional manifold at its class positions (intrinsic dimension, a loop in the first homology for calendar tokens), and which rows' activations parameterise position on it: an atlas whose charts are named by parameters.
3. Phase coding in weight space: whether the write rows of the neurons selective for weekdays have phases around the ring matching the day they select for; a population code on known parameters.
4. Manifold descendants: inject a parameterised ring along the weekday plane (and random planes as the control), follow its image through depth with the transport machinery (does it stay a loop, how fast does its radius contract, where is it re-written), and read the tangent through the Jacobian lens (what the model can say changes as the angle advances).
5. Planting a manifold: the pinning loss of e626 for a pair of rows carrying (cos, sin) of a cyclic variable, at an early checkpoint, since e627 showed trained models take the description and not the behaviour.
6. Where manifolds fail: the class-overlap graph's hubs (tokens where unrelated classes meet) as the plus-sign junctions the manifold assumption excludes.
Guardrail from the record: the row is not the concept, so a manifold's chart is a coalition's, never a single row's. All of 1 to 3 run on a Mac with Pythia-160m; 4 and 5 are small GPU jobs.
